The simple setup

Most users only need this flow: install the bridge at home, add the printer on the bridge setup page, sign into Tailscale, paste the bridge IP in the iPhone app.

  1. Open Terminal on your Ubuntu box.
  2. Paste this one command.
  3. Open the printed setup page and add your printer.
  4. The installer also prints the Tailscale bridge URL on port 8005 for iPhone Settings.
curl -fsSL https://raw.githubusercontent.com/ammarjmahmood/islicer/main/server/install.sh | bash
sudo tailscale up
tailscale ip -4
  1. Download the Mac bridge from this page.
  2. Launch it and open the bridge setup page.
  3. Add the printer on the Mac, then paste the Tailscale IP in iOS Settings.

Anywhere mode

Works off-network without exposing your printer

Tailscale gives your phone a private route to the bridge. The printer stays private at home, and the bridge is the only machine that needs printer LAN access. The bridge listens on TCP port 8005; Tailscale itself uses UDP 41641 for direct peer-to-peer tunnels when available.

If your bridge MacBook is at work or in your backpack, it can only print to the home printer when it has a VPN or subnet route back to the home LAN. The simplest setup is an always-on bridge at home.

Code review notes

What this build guarantees

The app now avoids unsupported direct cloud-print assumptions. Slicing requires a real engine on the bridge, and printer dispatch uses the local Bambu LAN pattern: FTPS file upload plus MQTT print command.

No fake slices

The bridge reports an error if CuraEngine or its definitions are missing instead of generating placeholder G-code.

Credentials stay home

LAN access codes and printer IPs are entered on the bridge setup page and stored in the bridge config, not in the iPhone app.

Remote path is explicit

Cellular printing works when the iPhone can reach the bridge through Tailscale, VPN, or a custom URL.
